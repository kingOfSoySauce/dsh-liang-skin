# 0.1.11 兼容性修复验证

本轮以 0.1.10 为基线。修复经过本地包验证和 Grok Build 4.7 最高可用推理等级（xhigh）只读 review 后，随 0.1.11 发布；Windows Desktop 仍需报告者更新后验证。

## 变更

- 保留宿主的根容器定位和层级，背景使用独立层级；兼容社区 Desktop 的标题栏高度。
- 保留官方 Windows 框架透明与 macOS 侧栏、新会话按钮配色修复；半透明背景遮罩统一绘制一次。
- 外观入口按原生三个主题按钮的结构识别，兼容构建类名哈希变化；停用时清理入口和监听。
- 人像逐张加载和解码，单张失败不阻止其他帧使用；失败后分别等待 0.5、1.5、3 秒重试，最多额外三次。
- 未加载的目标帧保留上一张可用人像；全部失败时保留配色背景。停用时取消重试和请求，重新启用后重新加载。
- 推理等级绑定使用宿主原生 Switch；仅点击开关切换，标题不可点击，移除附加说明与自绘开关样式。
- 保持素材原色、面板透明度及原有推理等级绑定语义。本轮不处理跨刷新外观记忆，也不修改皮肤市场。

## 本地验证包

验证包是完整的 `.tgz`，包含客户端构建与 24 张 WebP 人像；只用于本地验证。具体包路径、校验值和对应修复提交由交付消息提供。

官方 Desktop：使用当前宿主支持的本地包安装入口加载该 `.tgz`，由用户点击安装、启用和重启；不要把 Web profile 的安装结果当成 Desktop 已安装。若当前宿主没有本地包入口，先提供其实际入口信息，再选择安装路径，不直接编辑 profile。

DSH Web：可用 `dsh plugin --profile web add /绝对路径/测试包.tgz` 安装。安装或重新安装后完全停止并重新启动对应宿主；浏览器刷新不能替代 Desktop 完全退出重开。

## 用户验收

1. 安装测试包并完全退出、重开官方 Desktop，确认加载的是测试包；保留其他皮肤停用的状态。
2. 打开「设置 → 通用设置 → 外观」：应有「滑动变祖」和推理等级绑定开关；切原生后人物及滑块消失，点击滑动变祖后恢复。
3. 在浅色档和黑金档分别观察人物、侧栏和输入区；调整窗口大小、切换侧栏，确认无半屏断层、文字可读。
4. 拖动滑块：人物应随档位改变；关闭绑定后只改变人物和配色，不修改模型推理等级；点击绑定标题不会切换开关，开关外观应与原生「代码工作工具」一致。
5. 打开「完全权限」、模型选择和其他弹窗，确认显示层级正常且可以点击；标题栏仍可拖动，窗口按钮可用。
6. 刷新或重启时，外观仍按本次激活默认启用皮肤；跨刷新记住原生选择属于暂缓的 #9。

自动化测试使用浏览器宿主夹具并模拟图片失败；它们不代表官方 Windows Desktop 真机已经验收。
